## 2. 为什么这套风格成立

### 色彩先把页面变成“厨房里的东西”

大面积暖奶油底像纸张和旧食谱；鼠尾草灰绿同时出现在文字、插画、图标、按钮和选中导航中。这些重复的绿色建立统一感，真实食物照片承担大部分鲜艳颜色。少量黄、棕、橄榄色放在餐布上，红色主要用于移出等动作。

它不是把普通白色页面刷成绿色：底色的温度、纸张纹理、浅色实体按钮与深绿色选中态都参与了设计。

### 用材质区分区域，不依赖满屏卡片

纸张是底，餐布是菜单的承托面，盘子代表菜品，便签或纸片承担提示。用户不必读很多标题，就能理解哪些是内容、哪些是按钮。手绘线条略有不规则，阴影柔和，使页面不像管理后台。

参考中冰箱仍然使用纵向清单，而不是每个食材一张大图卡。这一点与我们此前确定的紧凑库存方向一致。

### 插画具有角色作用

手绘角色承担欢迎、空内容和陪伴感，而不只是装饰图标。但角色、品牌字形、插画是参考作品本身的识别资产。食隅记应拥有自己的图形：本稿画了餐锅、食谱本、碗盘和小叶子，没有复用 Civa 名称、角色或原图。

### 主动作容易辨认

主按钮为实心绿色，次按钮为奶油色，选中导航也用绿色。图标旁保留文字，不要求用户猜测。编辑以独立弹窗呈现，让用户专注当前动作。表单内的内容先分组，再展示输入与选择。

### 语气把任务转化为生活

页面标题是面向做饭的人说话，而不是资源管理术语。食隅记可在页头和空态使用少量生活化语言，但关键操作仍用明确动词：记录、保存、核对、确认、撤销。缺货与冲突提示必须交代对象、数量和下一步。

## 3. 有哪些地方需要重新设计

喜欢整体风格，不代表每一个交互都适合我们的任务。

| 参考中的处理 | 食隅记的取舍 | 原因 |
|---|---|---|
| 首屏大幅角色与食谱本 | 桌面页头小场景；手机压缩插画高度 | 减少每次打开都要向下找库存或餐单的距离 |
| 餐盘照片与大型转盘构图 | 第一版用菜名和小型厨具插画 | 当前菜品只存名字；照片上传、裁切、存储尚未进入业务范围 |
| 首页、冰箱、菜单、我的四入口 | 餐安排、库存、菜品三入口 | 承接当前信息架构，不引入空的个人中心 |
| 心愿、随机菜单、到期、周统计 | 保留参考分析，不进入食隅记页面 | 都不是本次已确认的 MVP 能力 |
| 部分大面积浅绿文字 | 正文使用更深的绿色 | 数量、单位、错误说明必须易读 |
| 大块立体按钮与宽松表单 | 主按钮保留质感；输入区降低阴影、压缩空白 | 减少噪声，避免重复出现“很大但内容很少”的表单 |
| 静态图未展示双人冲突与恢复 | 沿用食隅记已有后端规则，补齐对应 UI 状态 | 风格资料不能证明并发或事务逻辑，也不能替代它们 |

参考冰箱图右侧的数字不能直接当作库存量：原帖正文围绕到期时间介绍冰箱，静态图中数字也没有库存单位。本稿库存必须明确显示“3 个”“1.7 kg”，不挪用参考的数字语义。

## 4. 建议采用的设计语言

**方向名称：厨房手账。关键词：奶油纸、鼠尾草绿、轻手绘、餐布格纹、清楚的清单。**

以下是为食隅记配制的候选色值，不是 Civa 官方设计令牌。参考图经过截图和压缩，纸面还叠加纹理，所以只能得到一组近似颜色。对第 09 图进行像素分桶后，常见暖底接近 RGB(248,240,216)，绿色接近 RGB(96,112,104)；本稿据此调整正文对比度和交互层级。

| 角色 | 候选色 | 使用方式 |
|---|---|---|
| 页面纸底 | `#F7EFD9` | 大面积背景，暖黄而不是纯白 |
| 卡片与输入区域 | `#FFF9EB` / `#FCF6E9` | 让文字落在相对干净的表面 |
| 主绿色 | `#5D7665` | 主按钮、选中态、少量图标 |
| 重点绿色 | `#405E49` | 次要动作和分组标题 |
| 正文 | `#344C3D` | 字段、名称、核心数量说明 |
| 次要文字 | `#606E59` | 单位、日期、附加说明 |
| 细线 | `#D8DCC5` | 清单分隔、输入边界 |
| 可处理的缺口 | `#F6E8CB` + `#835A27` | 缺货提示，提供就地处理入口 |
| 输入错误 | `#F8E8DF` + `#9A4137` | 必须修改的具体字段；避免满屏红色 |

建议的视觉预算：大约八成区域是干净的暖纸与内容；手绘、格纹和强调色集中在少量位置。不是对原图做精确面积统计，而是防止实现时装饰失控的约束。

- 标题：本机楷体优先，保留手写气质；正文用系统中文无衬线字体。原型未引入网络字体，不宣称已识别参考的实际字体。
- 数量：清晰的大数字，单位紧随其后；不以粗字体或装饰影响小数和分数辨认。
- 常规正文 14px，次要说明 12px；手机标题约 26px，桌面 34–40px。
- 交互区域至少约 44px 高；食材行手机约 49px，桌面约 51px。数量输入只有一套。
- 卡片圆角 12–17px，主按钮为胶囊；大弹窗约 22–24px 圆角。
- 纸纹为自制低透明度纹理；不铺在输入字上形成视觉干扰。
- 深色是本稿扩展：绿黑纸底、米色文字、灰绿按钮。原帖没有提供深色方案，不能称为复刻。

## 5. 三个模块如何落地

### 餐安排

待完成餐单在上，已完成历史在下，沿用已有排序。每餐先见日期/餐次、菜名、必要缺口和核对入口；餐布只作为一条细的分区装饰。桌面右侧放已有的常用搭配，手机排列到后面，不占第一屏核心动作。

历史默认收起，展开见用量和复用/撤销入口。保存不扣库存；只有最终确认才进入已完成。

### 库存

顶部为查找、单个记录、批量记录，随后是位置标签与分类。手机食材行显示名字和数量；桌面/平板按类别组织为两列清单，限制行宽，避免一条食材横跨整个屏幕。

点食材看类别、位置及编辑/报废入口；全局处理记录始终在库存页可达。完整报废后，原食材从在库清单消失，记录入口仍然可用。

单个与批量使用相同语言，单个只显示一行；批量先选本批类别、位置和常用单位，空白行忽略。单位冲突在当前弹窗处理，可换算时带入计算结果，不可换算也有最终量输入。

### 菜品与搭配

菜品采用小图标和名字清单，编辑动作明确；常用搭配才使用有餐布边缘的便签卡。菜品只存名字，耗材仍归属本餐，没有借视觉设计恢复固定配方用量。

### 核对与失败恢复

每道菜下逐项列食材，一行包含名称、只读库存/预计量和一个实际量输入。缺口只解释一次，贴近发生问题的食材；最下方汇总要处理哪些食材，禁用确认按钮，并提供可执行路径。

原型演示了“库存不足 → 去库存处理 → 返回核对，保留实际输入”。待购买则是“去补货 → 返回菜单 → 明确关联已入库食材 → 核对”。正式整合时继续使用原有版本保护、短事务、未知结果核验与安全撤销机制。

## 6. 本次预览能操作什么

[打开预览](index.html)

预览默认使用 8 种库存、6 道菜、2 份搭配、3 条待完成餐单及 1 条历史示例。它们是为评审单独编写的样例，不是 Civa 的演示数据，也没有写入食隅记数据库。

可试用：三入口切换、位置/类别/名称筛选、食材详情、编辑、单个与批量记录、同名合并、部分/全部报废及全局撤销入口、菜名/搭配编辑、餐安排与耗材、缺口引导、实际量修改、完成后进入历史。

顶部“正常场景”可切换空数据、加载和读取失败示意；右上角切换亮暗主题。这些是评审控制，不属于正式产品菜单。刷新即还原内存示例。

**证据边界：**这是独立 HTML/CSS/JavaScript 交互原型，未连接真实 API。复杂的双人编辑冲突、菜单安全撤销、库存单位变更后的快照换算、取消菜单恢复等仍以现有正式应用为准，本原型不完整模拟这些后端规则。不能用预览替代已冻结模块的正式联调与验收。

## 7. 评审后进入正式前端的顺序

1. 用户评审配色、纸纹强度、插画风格、字体与密度，确定是否采用本方向。
2. 将确认的颜色、间距、按钮、弹窗和导航做成共享 UI 基础，先在库存落地。
3. 依次迁移菜品/搭配与餐安排，复用已经拆出的业务模块和真实 API。
4. 补齐完整状态矩阵：加载、空白、校验、缺口、过期版本、提交中、结果未知、安全恢复。
5. 按改动范围做真实 API 联调与手机/平板/桌面、亮暗主题验收，再处理用户反馈。

本稿新增的是视觉方向与评审原型；不需要新增数据库字段、migration、API 或部署。
