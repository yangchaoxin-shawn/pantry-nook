## 4. 前端实现

- 库存：真实列表、分类/名称/位置/状态筛选、录入、编辑、用完与丢弃。未确认作战存在时禁改数量；结束的食材只编辑元信息，避免暗示数量修改会恢复在库。
- 菜品：创建、修改与软删除。
- 搭配：创建、编辑菜品组合、删除和复制到作战；提示失效菜品重新选择。
- 作战：日期选择、直接选菜或复制模板、修改菜品、取消、无消耗历史的未确认记录删除。保存其他日期时自动切到该日期。
- 确认：选择真实库存、消耗原文、剩余原文及可选剩余数字、可选关联具体作战菜品；保留碳水/蔬菜/蛋白质提示。不猜测用量，整次作战统一确认。
- 撤销与历史：调用后端恢复事务，查询有效和已撤销消耗及前后余量；冲突显示后端原因。
- 首次加载、空数据、读取错误、表单错误、保存中与成功提示；请求取消和超时；防止重复点击。写入通信异常提示先刷新核对，不自动重试。
- API 类型来自契约，读取全部分页。编辑食材仅 PATCH 实际变更字段，改名称不会写回旧余量。业务数据不使用 localStorage。

## 5. 后端实现

数量计算使用 Decimal，对齐已有 NUMERIC(12,3)，修复 float/Decimal 混算和静默舍入；名称/数量/备注即使形似 JSON 也保持字符串。事务级咨询锁串行化计划状态与库存写入，关闭检查与写入之间的并发窗口；确认写消耗、改库存和状态保持同一事务。

同食材多条消耗按逆序恢复；后续有效消耗、状态不匹配时返回 409。用完时间使用 UTC；撤销恢复原结束时间。撤销后调整菜品时保留历史行及名称快照，阻止删除被历史消耗引用的菜品。单位不一致时要求用户人工填写剩余数字，不能自动换算。修复末页之外查询总数和连接池并发初始化。

详见 [V5 产品提案](v5-product-proposal.md)，每项已列产品含义、模型、API、状态、迁移及安全：

- D：建议随机链接只允许看反馈/留言，私有管理侧处理已读/采纳；30 天可撤销链接、反馈内真实待办。与设计稿“任何访客可管理”不同，须明确批准。
