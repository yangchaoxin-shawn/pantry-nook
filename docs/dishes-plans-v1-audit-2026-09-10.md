# 菜品与常用搭配 V1 审计

日期：2026-09-10
范围：菜品名称库、常用搭配模板，以及它们与菜单的复制关系。

## 1. 已实现并保持稳定的规则

| 规则 | 当前实现 | 结论 |
|---|---|---|
| 菜品只保存名称 | `dishes` 只保存菜品身份和名称 | 已实现 |
| 菜品可新增、编辑、删除、复用 | `POST/PATCH/DELETE /api/dishes`，名称去首尾空格且在有效菜品中唯一 | 已实现 |
| 新菜可在安排菜单时加入并选用 | 安排菜单页创建成功后直接选中；重名时复用已有菜品 | 已实现 |

| 使用搭配创建菜单时复制菜品 | 菜单保存菜名快照，之后编辑模板或菜品不改历史菜单 | 已实现 |
| 模板 CRUD 不影响已复制菜单 | 模板删除只删除模板本身 | 已实现 |

## 2. 本轮修复：删除菜品不能留下失效搭配

此前删除菜品会软删除菜品本身，但被引用的搭配仍保留该菜。之后从该搭配创建菜单会被后端拒绝，形成“看得到、用不了”的模板。

现已收敛为：

1. 菜品被一个或多个搭配引用时，后端拒绝删除，返回受影响搭配名称。
2. 前端点击删除前调用真实查询接口，直接显示受影响的搭配，并提供“查看常用搭配”。
3. 用户先编辑或删除搭配后，才能删除菜品。
4. 菜品未被搭配引用时，仍可软删除；历史菜单保留菜名快照。

该规则不自动改写多个搭配，也不影响库存、菜单或消耗历史。
