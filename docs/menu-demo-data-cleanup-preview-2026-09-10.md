## 2. 为什么不能直接在页面删除

这两条候选菜单已经确认，已经写入消耗记录。系统的正常规则会禁止删除有消耗历史的菜单，即使撤销确认，消耗记录也必须保留为“已撤销”证据。这是为了确保撤销库存和历史可追溯，不应为了清理演示数据绕过。

此外，这些菜单之后已经出现过其他确认、库存编辑和报废恢复。按历史倒序撤销候选菜单有可能因库存版本变化被拒绝；强行恢复旧库存会覆盖后续正确变化。

## 3. 推荐的安全整理方案

以**当前库存为最终事实**，不尝试按旧菜单反推或改变任何库存量：

1. 在维护前创建数据库备份。
2. 精确删除候选菜单的消耗记录、备餐关联、菜品快照和菜单记录。
3. 将两道候选菜品软删除，使其不再出现在菜品选择列表。
4. 不删除食材，不修改当前食材库存，不动其他菜单、搭配或消耗历史。
5. 维护后检查候选名称不再出现在菜单页、菜品页和 API 列表，且当前库存与维护前一致。

这是一项一次性数据维护，不作为用户日常功能，也不通过前端“删除”按钮伪装执行。
