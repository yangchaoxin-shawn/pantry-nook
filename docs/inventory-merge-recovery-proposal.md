# 合并撤销：已批准实施规格

2026-09-12。用户已批准并实施，当前规则同步到 PRD；实际验证及未覆盖范围见 [交付记录](inventory-merge-recovery-delivery.md)。migration 009 已在备份后执行。

## 产品含义

旧食材全部报废或用完后，已经重新入库同名食材，撤销旧处理时提供“合并恢复”弹窗。现有库存继续保留，旧记录只恢复一次。

例：旧鸡蛋 3 个全部报废，后来又买了 5 个；撤销旧报废时显示“现有 5 个 + 恢复 3 个 = 合并后 8 个”。点击确认后才保存，取消不改数据。

- 整餐只处理“旧库存无后续变化，但存在同名新库存”的冲突；报废撤销已扩展为按本次报废量补回当前库存（包括原 ID 后续补货），确认仍检查最新版本。
- 最终保留当前在库食材的 ID、名称、分类、位置和备注；跨 ID 时旧食材留作历史，不复活第二条在库记录；原 ID 加回时只更新这一条。
- 默认沿用现有库存单位；支持选择旧单位。质量/体积的已支持换算按 Decimal 计算；不同量纲不猜测，要求填写确认后的最终数量和单位。
- 恢复整餐若有多项冲突，在同一弹窗一次核对；不得逐项提交造成半餐撤销。

## 数据模型

新增只追加的 `inventory_recovery_merges` 审计表，保存：

- 来源：报废 adjustment_id 或菜单 consumption_id（二选一，外键保留）；一个来源只能被合并恢复一次。
- source_ingredient_id、target_ingredient_id：旧历史食材和最终在库食材。
- restored_text/value/unit：恢复数量；target_before_* 和 target_after_*：目标合并前后快照。
- calculation_mode（换算/人工确认）、created_at；数量与现有 NUMERIC(15,6) 对齐。

历史调整/消耗仍标记 reversed；历史读取附带“已合并恢复到某食材”的结果。旧食材保留 inactive 状态，不能仅凭 reversed 就假定旧 ID 已重新入库。

## API 设计

- 新增 `GET /api/ingredients/adjustments/{id}/recovery-preview`、`GET /api/daily-battles/{id}/recovery-preview`：只读，返回可撤销性、冲突目标、源/目标版本和建议结果。预览不占库存。
- 现有两个撤销 POST 扩展可选 `merge_resolutions`。每项带源与目标食材 ID、目标版本、最终单位；不能自动换算时再提交人工最终数量原文和数值。
- 客户端还提交预览时的源记录/菜单版本。后端在事务内重新读取来源状态、目标名称/状态、版本、单位和范围；不信任客户端提交的恢复量。
- 未提交选择时返回 409 `MERGE_REQUIRED`；预览过期返回 409 `RECORD_CHANGED`，前端保留输入并引导重新核对。
- 沿用成功 `{data}`、错误 `{error}`；OpenAPI 和前端生成类型同步更新。

## 状态与事务

1. 打开撤销预览，仅展示；没有占用或扣减。
2. 确认时取得现有库存事务咨询锁，与所有库存写操作串行；按食材 ID 顺序读取来源、目标和历史记录并校验。
3. 校验旧记录可安全撤销、整餐合并源与目标不同（报废允许相同）、当前同名在库唯一、目标版本未变。
4. 换算并汇总本次恢复总量；检查最终量大于 0、精度和上限。
5. 一个事务内：写目标库存 → 写合并审计 → 反转旧历史 → 更新菜单状态。任何一项失败全部回滚。
6. 菜单恢复到待完成时，本菜单关联的旧耗材改为最终库存 ID；受影响预计量清空，提示重新核对并补全，避免旧单位误当成新单位。其他菜单不自动重写。
7. 重复点击或双人同时撤销，仅第一次成功。该合并不提供独立的“再撤销合并”按钮；需要再做这餐时重新核对确认，形成新的消耗历史。

## 数据库迁移影响

新增表、外键和来源唯一约束；不删除或清洗历史数据，不移动历史 ID。更新 schema 快照并在独立库验证空库初始化、旧库升级、重复 migration。
合并功能上线前已有数据保持原样；用户库迁移遵循项目当前备份与授权约定。

## 安全与公开访问

不增加角色、公开链接或权限。数量和版本由后端校验，所有 SQL 参数化；沿用现有本地访问边界。公开部署仍需另行设计访问保护。

## 必须验证的场景

报废恢复 3+5=8、整餐多项合并、可换算单位、不可换算人工值、取消保留输入、预览期间补货导致版本冲突、整餐中一项失败全部回滚、并发仅恢复一次、历史入口能说明合并去向、恢复菜单后必须补齐受影响用量。测试只写独立库。

取消后的输入只保存在当前页面内存，刷新整页后不保留；重新打开仍重新读取库存版本。多道菜共用食材时，每条消耗审计保存各自恢复量，目标前后快照表示整次合并的结果，不能将这些目标快照再次求和。
