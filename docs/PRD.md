# 食隅记 Pantry Nook 产品需求文档（PRD）

- **版本**：v0.3
- **状态**：基础逻辑确认版
- **更新时间**：2026-09-05
- **产品形态**：响应式 Web，后续支持添加到手机/平板主屏幕
- **目标平台**：Windows、iPhone、iPad、Android
- **使用方式**：个人使用，自建后端和数据库

---

## 1. 产品目标

食隅记先解决一条最基础的链路：

```text
家里有什么食材
→ 可以做哪些菜
→ 今天计划吃什么
→ 实际做完后用了哪些食材
→ 确认并调整库存
```

第一版只实现这条链路，不做复杂菜谱、营养分析、AI 识别或知识库。

---

## 2. 核心对象

产品包含四个基础对象。功能上仍然围绕“库存、菜品、消耗”三个核心模块展开，“今日作战”负责把它们连接起来。

### 2.1 食材库存

表示家里当前拥有的食材。

第一版字段：

```text
食材名称
食材分类
数量
单位/份数
当前剩余数量
状态
```

状态先使用：

```text
库存中
已用完
```

第一版暂不处理批次、保质期、存放位置和复杂的单位换算。

### 2.2 菜品

表示一个可以保存、以后反复选择的菜品名称。

例如：

```text
米饭
西红柿炒鸡蛋
蒜苔炒肉
奥尔良鸡翅
苦瓜炒蛋
```

第一版菜品只保存：

```text
菜品名称
```

暂不保存配料、做法、来源、图片、营养信息和标签。

菜品不固定绑定库存食材。保存“西红柿炒鸡蛋”时，不自动指定必须使用哪几个西红柿或鸡蛋；真正做菜时再从库存中选择实际使用的食材。

### 2.3 搭配方案

表示多个菜品组成的一套推荐搭配。

例如：

```text
杂粮饭 + 香煎去骨鸡腿肉 + 西兰花 + 胡萝卜
```

搭配方案需要保留整体关系，同时每个组成部分仍然是独立菜品：

```text
搭配方案
├── 杂粮饭
├── 香煎去骨鸡腿肉
├── 西兰花
└── 胡萝卜
```

搭配方案的作用：

- 保存看到的推荐组合；
- 以后可以整体拿来创建今日作战；
- 可以拆开其中的菜品；
- 可以在此基础上重新组合；
- 不影响库存，也不会自动产生消耗。

第一版搭配方案只需要保存：

```text
方案名称（可选）
包含的菜品
```

不需要保存推荐人、来源、配料、做法或推荐理由。

### 2.4 今日作战

表示某一天计划做什么，以及最后实际做了什么。

它是库存、菜品和消耗之间的连接对象。

一条今日作战包含：

```text
日期
计划中的菜品
可选：来自哪个搭配方案
实际使用的库存食材
消耗记录
状态
```

“今日作战”可以从搭配方案创建，也可以直接选择多个菜品创建。

从搭配方案创建后，菜品会复制到今日作战中；用户可以根据当天库存进行调整，不会修改原搭配方案。

---

## 3. 今日作战状态和确认机制

这是第一版的核心逻辑。

### 3.1 计划中

用户先选择今天准备吃的菜：

```text
选择一个搭配方案
或手动选择多个菜品
```

此时允许调整菜品，例如删掉没有食材的菜、换成另一个菜。

计划中状态下：

```text
不调整库存
不生成正式消耗
```

### 3.2 已确认

实际做完饭后，用户核对：

```text
最终做了哪些菜
实际使用了哪些库存食材
每种食材用了多少
```

点击“确认做完”后，系统才执行：

```text
保存最终菜品
保存消耗记录
调整对应库存
将今日作战改为已确认
```

库存调整和消耗记录保存必须作为一次完整操作处理，不能只完成一半。

### 3.3 已取消

如果当天没有做，或者计划最终放弃：

```text
计划中 → 已取消
```

已取消的今日作战：

```text
不调整库存
不生成消耗
```

未确认的计划允许直接删除；是否保留已取消记录，第一版可以先保留，后续再决定是否提供历史查看。

### 3.4 撤销确认

如果已经确认，但后来发现当天其实没做，或者记录错误：

```text
撤销确认
→ 恢复确认前的库存状态
→ 撤销本次消耗
→ 今日作战回到计划中或改为已取消
```

如果已经确认的消耗无法可靠恢复，必须提示用户手动确认剩余数量，不能擅自猜测。

## 4. 食材消耗逻辑

食材消耗只记录“实际做菜时用了什么”，不记录菜品理论上应该用什么。

一条消耗至少包含：

```text
对应今日作战
对应库存食材
消耗数量
单位/份数
```

可选关联具体菜品，例如：

```text
今日作战：米饭 + 西红柿炒鸡蛋
库存食材：西红柿
消耗数量：1 个
关联菜品：西红柿炒鸡蛋
```

第一版原则：

1. 消耗必须指向一条实际库存记录。
2. 只有今日作战确认后，消耗才正式生效。
3. 计划中的菜品不会自动产生消耗。
4. 消耗记录需要保留，不能因为库存用完就消失。
5. 消耗数量先支持简单的数量和单位，例如“1 个”“1 份”“2 个”。
6. 无法准确换算时，由用户填写确认后的剩余数量。

## 5. 食材分类

按照用户每顿饭关注的结构，第一版使用以下分类：

```text
碳水
蔬菜
蛋白质
水果
其他
```

主要关注：

```text
碳水 + 蔬菜 + 蛋白质
```

这只是日常搭配提示，不做专业营养评估。

### 分类原则

```text
米饭、面、馒头、手抓饼、板栗等 → 碳水
各种新鲜蔬菜 → 蔬菜
肉、禽、鱼、虾、蛋等 → 蛋白质
橙子、葡萄、橘子等 → 水果
暂时无法判断或不属于以上几类 → 其他
```

同一个食材的分类允许后续修改。

## 6. Word 内容对应关系

### 家里清单 → 食材库存

例如：

```text
一份沙葱
一份茭白
一个西红柿
一份菜花
两份小前腿猪肉
3 份乌冬面
四五个橙子
一串葡萄
```

数量先按原文或人工确认后的简单数量录入。

### 推荐菜品 → 搭配方案

例如：

```text
1. 杂粮饭 + 香煎去骨鸡腿肉 + 西兰花 + 胡萝卜
2. 白米饭 + 猪里脊肉丝 + 青椒豆干
3. 白米饭 + 卤牛腱子 + 花菜 + 杏鲍菇
4. 杂粮饭 + 老豆腐红烧 + 西葫芦炒木耳
```

每一行保存为一个搭配方案，同时拆出其中的菜品。

### 已做菜内容 → 今日作战历史

```text
8.31 米饭 + 奥尔良鸡翅 + 苦瓜炒蛋
9.1 米饭 + 蒜苔炒肉 + 西红柿炒鸡蛋
```

对应两条已经发生的今日作战记录。历史导入时需要确认日期年份。

### 已消耗的食物 → 消耗记录

```text
8.31：一份鸡翅、一条苦瓜切片
9.1：一顿蒜苔、一份大前腿猪肉、一个西红柿
```

如果无法确定对应哪一条库存，录入时由用户选择，不能自动猜测。

## 7. 第一版功能范围

### 库存

- 添加食材
- 修改食材名称、分类、数量和剩余数量
- 查看当前库存
- 按碳水、蔬菜、蛋白质、水果、其他分类查看
- 标记已用完

### 菜品

- 添加菜品名称
- 修改菜品名称
- 删除菜品
- 从菜品库中选择菜品

### 搭配方案

- 创建搭配方案
- 添加多个菜品
- 修改方案中的菜品
- 保留推荐组合
- 从搭配方案创建今日作战
- 创建今日作战后允许单独调整菜品

### 今日作战和消耗

- 选择日期
- 选择一个或多个菜品
- 可从搭配方案快速创建
- 查看当天计划
- 选择实际使用的库存食材
- 填写消耗数量
- 确认做完并调整库存
- 取消未执行的计划
- 撤销错误的确认
- 查看历史记录和消耗记录

## 9. 底层关系

```text
一个菜品
    可以加入多个搭配方案
    可以出现在多条今日作战中

一个搭配方案
    包含多个菜品
    可以创建多条今日作战

一条今日作战
    包含多个菜品
    包含多条实际消耗

一条库存食材
    可以被多条消耗记录使用

一条消耗记录
    连接一条今日作战和一条库存食材
```

关系示意：

```text
搭配方案 ──复制菜品──→ 今日作战 ──确认后生成──→ 消耗记录 ──调整──→ 食材库存
      │                    │                         │
      └──包含多个菜品───────┘                         └──可关联具体菜品
```

## 10. 第一版验收标准

### 库存

- 可以添加“西红柿、蔬菜、2 个”。
- 可以添加“鸡蛋、蛋白质、6 个”。
- 可以修改剩余数量。
- 可以标记某条食材已用完。
- 库存可以按五个分类查看。

### 菜品和搭配

- 可以保存“西红柿炒鸡蛋”。
- 可以保存“家常晚餐”搭配方案，包含米饭、西红柿炒鸡蛋等多个菜品。
- 可以从搭配方案中删除一个菜品，但不影响原有菜品。
- 可以保留原搭配方案，同时单独使用其中的菜品。

### 今日作战

- 可以创建今天的计划。
- 可以从搭配方案复制菜品。
- 复制后可以调整今天实际准备做的菜。
- 未确认前，库存不发生变化。
- 确认后，才生成正式消耗并调整库存。
- 如果当天没有做，可以取消计划，库存不发生变化。
- 已确认记录可以撤销，库存和消耗能够回退或要求用户重新确认。

### 三类搭配提示

- 系统可以根据本次选择的库存食材显示是否包含：
  - 碳水
  - 蔬菜
  - 蛋白质
- 这只是提示，不替代营养判断。

## 11. 开发顺序

```text
1. 确认本需求文档
2. 初始化 Git
3. 按本文件重做后端数据结构和接口
4. 用 Word 内容准备第一批测试数据
5. 验证库存 → 菜品 → 搭配方案 → 今日作战 → 确认消耗 → 库存调整
6. 再设计前端页面和操作流程
7. 最后做移动端适配、PWA 和生产部署
```

当前不以旧前端页面为基础继续修饰。旧页面只是早期验证页面，后续按照本需求重新设计。
