## 本轮处理

| 用户反馈 | 落实结果 |
|---|---|
| 位置可不填，但应提醒补全 | 待补位置标记、全库存计数与筛选，点击直达位置字段 |
| 数量滚动精度过细 | 明确 ±1 控件，手动小数保留；聚焦才响应滚轮；批量手机行分层排布 |
| 仅改单位无法保存 | 按需成组发送数量原文、值、单位；数量不变可保存属性修改，分数原文保留 |
| 子页没有归属与返回 | 处理记录、常用搭配加入父级路径及返回；恢复父页搜索、筛选、滚动位置 |
| 菜品布局与手机按钮比例 | 连续手写菜品簿，按菜名长度自然排列；手绘标记、完整换行与 6:4 编辑/删除区域 |
| 核对仍显示旧库存、补货后走丢 | 首开/返回/前台定时重读；同一餐内补货、关联、继续核对；实际量草稿保留 |
| 历史及新餐安排缺少时间感 | 日期时间线与同日餐次分组，待完成/历史分区，保留筛选、展开记录及全部原操作 |
| 补货后还要手动关联 | 本次提交名称精确同名、有效同名库存唯一、菜单仍待完成、预计量单位可安全换算且无同菜重复耗材时，默认保存关联并回到原核对；提供“修改关联”入口 |
| 自动关联存在歧义或失败 | 菜单仍待完成时，名称不一致、候选不唯一、单位不安全或关联失效进入人工修改；补货期间菜单已确认或取消时直接回只读核对并说明最新状态，不进入编辑；已成功补货后只重试读取/关联，不重复入库 |
| 餐安排绑定库存不够高效 | 每道菜的库存候选增加全部、碳水、蔬菜、蛋白质、水果、其他筛选及数量；新增、待购关联和失效替换共用，已绑定项保持可见 |
| 之前批准的插画和小人尚未进入正式页面 | 菜品按稳定业务 ID 映射小人，同一菜品在菜品簿和餐安排时间线一致；菜品页接入“菜谱时刻”，餐安排页接入“厨房伙伴”页头插画 |

额外修复本次流程暴露的边界：同数字重填新单位、菜单并发修改叠加库存换单位、入库成功后关联失败不再重复入库、未知结果按实际提交名称核对。

## 用户重点验收

1. 从核对补货后，安全同名是否能直接回到原餐；“修改关联”、仍可编辑的歧义处理及菜单终态的只读说明是否清楚，并且没有重复补货。
2. 为每道菜绑定食材时，库存大类筛选与候选数量是否让查找更快，手机操作是否顺手。
3. 同一道菜在菜品簿和餐安排时间线的小人是否一致；菜品与餐安排页头插画是否自然、不过度抢内容。
4. 继续验收菜品簿的自由排布、库存补位置与数量修改、日期时间线等上一批反馈。
