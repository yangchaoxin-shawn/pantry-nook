## 4. 前端实现内容

- 主入口为“菜单 / 库存 / 菜品”，不展示接口设置。
- 库存仅展示在库食材，按大类分组，行内只放名称与余量，点击查看详情。
- 菜单选择日期和餐次，选已有菜名或就地“添加并选用”。菜品仅保存名字；CRUD 和常用搭配保留。
- 菜单可先保存为草稿，再为本次菜单的每道菜选择现有食材和预计用量；保存后可展开备餐单，刷新仍保留。
- 做完时会校验每道菜的耗材和预计用量，再按菜填写实际用量。库存仅只读展示；同一种食材的实际用量由系统汇总后一次性更新库存。
- 待完成在上，已完成/已取消在下，同屏按日期与餐次倒序。支持历史日期筛选、展开用料、再吃一次、撤销。
- “再吃一次”复制菜名供复用，不自动套用旧用量或旧库存关联。

## 5. 后端实现内容

- 菜单创建/更新同时保存餐次、菜名快照和备餐关联，备餐不预扣库存。
- 确认在一个事务中写入实际消耗、更新库存和菜单状态；失败全部回滚。
- 新确认模式校验菜单与库存 `updated_at`，拒绝过期核对结果；重复确认返回冲突。
- 同一食材用于多菜：保留每道菜实际用量原文，整餐剩余仅应用一次。现有消耗快照链中前面的同食材行维持原库存，最后一行应用整餐余量；这些是事务记账边界，不是推算出的各菜数字用量。撤销按逆序校验和恢复。
- 撤销保留历史；有正式消耗引用的菜单删除返回 409，修复此场景之前的 500。
- 继续保留未完成菜单期间禁止直接新增库存/改量的原有约束。

- 创建/编辑支持备餐关联；编辑省略该字段保持原值，空数组可将菜单暂存为未完成草稿；确认前必须补全每道菜的耗材和预计用量。
