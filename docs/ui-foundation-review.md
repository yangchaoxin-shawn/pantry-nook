# 第一批正式 UI：review 清单

2026-09-14。用户已确认 V6 + 约 50% 纹理；本批完成公共视觉、独立环境和真实 API 库存清单，正式界面待用户验收。

## 先看这里

[打开新评审页面](http://127.0.0.1:5200/)，点击“库存”。5194 保留原型对照，5173 仍是原有应用。三者用途不同。

本批开发目录为 `.worktrees/ui-foundation`，分支 `codex/ui-foundation`。代码未合并回原运行目录，避免热更新影响现有验收。启动与恢复详见 [评审环境](ui-review-environment.md)。

建议按以下顺序 review：

1. 看库存页背景、手写字、透明插画和列表密度，切换亮暗主题。50% 只作用于纹理，文字和插画没有降透明度。
2. 切换冷藏、室温、冷冻，再按大类或名称找食材。初始冷冻为空，应看到空态；冷藏有 5 种食材。
3. 点击一条食材看详情，再关闭；单个/批量录入入口继续使用已有真实表单。
4. 查看“变质 / 损坏记录”全局入口。它不依赖某条食材是否还在库存里。

新测试库已通过真实 API 初始化 8 种库存、6 道菜、2 个搭配和 5 条菜单。原验收库没有清空、替换或迁移；操作新页面只影响独立测试库。测试数据会随实际使用变化。

## 验证细节与边界

- 冷藏筛选只返回其 5 种食材；重复点击保持列表。冷冻请求真实返回空列表，错误和空态没有同时显示。
- 手机单个记录弹窗宽 347px，位于 375px 内容视口内；Esc 后焦点返回原“单个记录”按钮。库存列表只显示名字和量，详情保留编辑、处理变质/损坏入口。
- 人为停止的只有本批身份校验后的 3018/5200 服务；页面出现读取中，随后明确提示无法连接。恢复服务后 Vite 自动重新加载，库存成功重新读取。这次不把自动重载恢复写成“原弹窗内重试按钮恢复已验证”。
- 原 3000/5173/5194 监听进程保持；启动器可重复启动、复用测试数据，端口冲突时拒绝启动。默认代理仍是 3000，只有评审脚本显式指向独立端口。
- 浏览器尺寸控制与截图存在缩放差异，因此手机/平板改用明确宽度的真实应用 iframe，并检查实际 DOM 宽度、列数与交互。临时测试页面已移至 ignored `.review/viewport.html`，不会成为产品功能。
- 本批用现有库存表单验证共享样式和入口，未宣称全部表单业务已经在新视觉中重测；后续按模块继续验证。
